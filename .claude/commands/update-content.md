description: Add or edit a service or city page on HomeServicesResource.com, regenerate the static site, and deploy
---

You are updating content on HomeServicesResource.com, a static (no build-step-at-runtime) site generated from structured data. The site is generated by `build/generate.js` from `build/services-data.js` and `build/cities-data.js`, producing `index.html`, `about.html`, `services/*.html`, `areas/*.html`, `sitemap.xml`, and `robots.txt`. Homepage/about copy that mentions the service and city counts is derived automatically from `services.length`/`cities.length` in `generate.js` — no need to hunt down hardcoded numbers when adding an entry. Never hand-edit the generated HTML files directly — always edit the data files and regenerate.

## 1. Figure out what's being requested

Ask the user (if not already clear) whether this is:
- A new service, or an edit to an existing service → `build/services-data.js`
- A new city, or an edit to an existing city → `build/cities-data.js`

## 2. Edit the data

**Service object shape** (`build/services-data.js`):
```js
{
  slug: "kebab-case-slug",              // becomes /services/slug.html
  name: "Display Name",
  metaDesc: "~150-160 char meta description",
  overview: `300+ word paragraph explaining what the service involves`,
  costInfo: {
    intro: "one sentence framing the cost table",
    items: [{ label: "Project/size", range: "$X–$Y" }, ...],
    note: "caveat sentence about pricing variance"
  },
  howToChoose: ["tip 1", "tip 2", ...],  // 4-6 items
  faqs: [{ q: "...", a: "..." }, ...]    // exactly 4 items, service-specific
}
```

**City object shape** (`build/cities-data.js`):
```js
{
  slug: "kebab-case-slug",              // becomes /areas/slug.html
  name: "Display Name",
  county: "X County",
  intro: `150-250 word paragraph with genuine local context (county, housing stock age, growth, HOA prevalence, etc.)`,
  faqs: [{ q: "...", a: "..." }, ...]   // exactly 3 items; generate.js auto-appends a 4th seasonal FAQ
}
```

**Critical rules — do not violate these, they're load-bearing for the site's SEO/backlink strategy:**

1. **Outbound links only happen through a service's `partner` field.** A handful of services are paired with a partner business's own local-service site (currently: `junk-removal` → indianapolisjunkremoval.org, `dumpster-rental` → dumpsterrentalindianapolis.org, `home-inspection` → indianapolishomeinspectionservices.com, `pressure-washing` → powerwashingindianapolisin.com). A service object with a `partner` field gets:
   - One contextual link in its own `overview` text, written as inline markdown `[anchor text](https://partnerdomain.com/)` — `generate.js` auto-converts that pattern into a real `<a>` tag.
   - One outbound link per city page, automatically generated by `generate.js` for that service's row in every city's service list (replacing the usual internal link), with anchor text varied per city/service via `PARTNER_ANCHOR_TEMPLATES`.

   `partner` shape:
   ```js
   partner: { baseUrl: "https://partnerdomain.com/", extension: ".html" or "", anchorLabel: "lowercase label, e.g. 'dumpster rental'" }
   ```
   The per-city URL is built as `baseUrl + citySlug + extension`, with Indianapolis mapping to the partner's homepage (`baseUrl` alone) — this assumes the partner site's city-slug format matches ours exactly. **Before adding a new partner, verify that with a quick fetch of the partner site's city pages** (e.g. does `/carmel` or `/carmel.html` actually exist, and is Beech Grove hyphenated the same way). If a partner's city coverage or URL shape doesn't match ours 1:1, don't force it into this generic system — ask how to handle the mismatch instead of guessing.
2. **Never add `[text](url)` bracket syntax to a service's `overview` unless that service has a `partner` field** — the markdown-link conversion in `generate.js` is unconditional, so stray brackets anywhere will silently create an unintended outbound link.
3. Services without a `partner` field must stay purely informational — no outbound links, ever.
4. Keep `overview` for services and `intro` for cities substantive (300+ words for services, 150-250+ for cities) — thin pages defeat the site's SEO purpose.

## 3. Regenerate the static site

```bash
node build/generate.js
```

This rebuilds every HTML page plus `sitemap.xml` and `robots.txt` from the data files. It's safe to run repeatedly — it always regenerates from scratch.

## 4. Verify before shipping

Run these sanity checks (adapt paths if only one new/changed page):

```bash
# JSON-LD is valid on every page
node -e "
const fs=require('fs');
const files = fs.readdirSync('services').map(f=>'services/'+f).concat(fs.readdirSync('areas').map(f=>'areas/'+f), ['index.html','about.html']);
let errors=[];
for (const f of files) {
  const html = fs.readFileSync(f,'utf8');
  for (const s of [...html.matchAll(/<script type=\"application\/ld\+json\">([^<]+)<\/script>/g)].map(m=>m[1])) {
    try { JSON.parse(s); } catch(e) { errors.push(f+': '+e.message); }
  }
}
console.log(errors.length?errors.join('\n'):'ALL JSON-LD VALID');
"

# Backlink rule still holds for every partner: 1 link on its own service page,
# 1 per city page, nowhere else. Repeat for each domain in a `partner.baseUrl`
# across build/services-data.js.
grep -rc "indianapolisjunkremoval.org" services/*.html areas/*.html index.html about.html | grep -v ":0"
grep -rc "dumpsterrentalindianapolis.org" services/*.html areas/*.html index.html about.html | grep -v ":0"
grep -rc "indianapolishomeinspectionservices.com" services/*.html areas/*.html index.html about.html | grep -v ":0"
grep -rc "powerwashingindianapolisin.com" services/*.html areas/*.html index.html about.html | grep -v ":0"
```

Also open the new/changed page(s) and spot-check: title/meta description look right, breadcrumb is correct, FAQ accordion renders, and (for a new page) it's reachable from the homepage grid and from the reciprocal service↔city link lists.

If this is a **brand new** service or city, double check it now appears in `sitemap.xml`.

## 5. Commit and push

```bash
git add -A
git status --short   # review what's staged before committing
git commit -m "Add/update <service or city name>"
git push
```

GitHub Pages redeploys automatically from `main` within a minute or two of the push — no other action needed.
