description: Add or edit a service or city page on HomeServicesResource.com, regenerate the static site, and deploy
---

You are updating content on HomeServicesResource.com, a static (no build-step-at-runtime) site generated from structured data. The site is generated by `build/generate.js` from `build/services-data.js` (17 services) and `build/cities-data.js` (14 cities), producing `index.html`, `about.html`, `services/*.html`, `areas/*.html`, `sitemap.xml`, and `robots.txt`. Never hand-edit the generated HTML files directly — always edit the data files and regenerate.

## 1. Figure out what's being requested

Ask the user (if not already clear) whether this is:
- A new service, or an edit to an existing service → `build/services-data.js`
- A new city, or an edit to an existing city → `build/cities-data.js`

## 2. Edit the data

**Service object shape** (`build/services-data.js`):
```js
{
  slug: "kebab-case-slug",              // becomes /services/slug.html
  name: "Display Name",
  metaDesc: "~150-160 char meta description",
  overview: `300+ word paragraph explaining what the service involves`,
  costInfo: {
    intro: "one sentence framing the cost table",
    items: [{ label: "Project/size", range: "$X–$Y" }, ...],
    note: "caveat sentence about pricing variance"
  },
  howToChoose: ["tip 1", "tip 2", ...],  // 4-6 items
  faqs: [{ q: "...", a: "..." }, ...]    // exactly 4 items, service-specific
}
```

**City object shape** (`build/cities-data.js`):
```js
{
  slug: "kebab-case-slug",              // becomes /areas/slug.html
  name: "Display Name",
  county: "X County",
  jrSlug: "matching-slug-or-null",      // see rule below
  intro: `150-250 word paragraph with genuine local context (county, housing stock age, growth, HOA prevalence, etc.)`,
  faqs: [{ q: "...", a: "..." }, ...]   // exactly 3 items; generate.js auto-appends a 4th seasonal FAQ
}
```

**Critical rules — do not violate these, they're load-bearing for the site's SEO/backlink strategy:**

1. **Only the `junk-removal` service overview may contain an outbound link**, written as inline markdown `[anchor text](https://indianapolisjunkremoval.org/)` — `generate.js` auto-converts that pattern into a real `<a>` tag. **Never** use `[text](url)` bracket syntax in any other service's `overview` field, or it will silently create an unwanted outbound link on that page.
2. **`jrSlug` on a city** determines the one outbound link on that city's "Junk Removal" list item, pointing to `https://indianapolisjunkremoval.org/{jrSlug}.html`. The partner site currently has pages for: avon, beech-grove, brownsburg, carmel, fishers, greenwood, lawrence, lebanon, noblesville, plainfield, speedway, westfield, zionsville, plus Indianapolis at the homepage (use `jrSlug: null` for Indianapolis or any city not on that list — it falls back to the partner's homepage).
3. Every other service (all 16 non-junk-removal services) must stay purely informational — no outbound links, ever.
4. Keep `overview` for services and `intro` for cities substantive (300+ words for services, 150-250+ for cities) — thin pages defeat the site's SEO purpose.

## 3. Regenerate the static site

```bash
node build/generate.js
```

This rebuilds every HTML page plus `sitemap.xml` and `robots.txt` from the data files. It's safe to run repeatedly — it always regenerates from scratch.

## 4. Verify before shipping

Run these sanity checks (adapt paths if only one new/changed page):

```bash
# JSON-LD is valid on every page
node -e "
const fs=require('fs');
const files = fs.readdirSync('services').map(f=>'services/'+f).concat(fs.readdirSync('areas').map(f=>'areas/'+f), ['index.html','about.html']);
let errors=[];
for (const f of files) {
  const html = fs.readFileSync(f,'utf8');
  for (const s of [...html.matchAll(/<script type=\"application\/ld\+json\">([^<]+)<\/script>/g)].map(m=>m[1])) {
    try { JSON.parse(s); } catch(e) { errors.push(f+': '+e.message); }
  }
}
console.log(errors.length?errors.join('\n'):'ALL JSON-LD VALID');
"

# Backlink rule still holds: junk-removal.html (1) + exactly one per city page, nowhere else
grep -rc "indianapolisjunkremoval.org" services/*.html areas/*.html index.html about.html | grep -v ":0"
```

Also open the new/changed page(s) and spot-check: title/meta description look right, breadcrumb is correct, FAQ accordion renders, and (for a new page) it's reachable from the homepage grid and from the reciprocal service↔city link lists.

If this is a **brand new** service or city, double check it now appears in `sitemap.xml`.

## 5. Commit and push

```bash
git add -A
git status --short   # review what's staged before committing
git commit -m "Add/update <service or city name>"
git push
```

GitHub Pages redeploys automatically from `main` within a minute or two of the push — no other action needed.
